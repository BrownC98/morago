# 소리 입력 수동 시험(실제 Windows·macOS 기기)

CI 러너에는 소리 장치가 없다. 아래 시험은 실제 기기에서 한 번씩 한다. 결과는 이 파일 끝에 날짜와 함께 적는다.

1. `cd src-tauri`
2. 마이크: `cargo run --release --example capture -- mic 10 mic.wav`. 10초 동안 말한다. 마이크 이름, 시스템 소리 지원 여부, 조각 수, 길이, 최댓값을 보인다. WAV는 16 kHz 모노, 약 10초이고 목소리가 들려야 한다(최댓값 > 0.01). 무음이면 경고를 보인다.
3. 시스템 소리: 음악이나 영상을 틀고 `cargo run --release --example capture -- system 10 sys.wav`. WAV에 튼 소리가 있어야 한다. 중간에 몇 초 멈춰도 파일 길이가 유지되고 멈춘 뒤의 소리가 시간에 맞아야 한다.
4. 동시: 두 터미널에서 mic와 system을 함께 시작하고, 틀어 놓은 소리 위로 사람이 말한다. 두 WAV에서 목소리와 소리가 약 100 ms 안에서 같이 시작해야 한다.
5. macOS: 처음 실행하면 터미널 앱에 권한 창이 뜬다. 허용한 뒤 다시 실행한다. macOS 14.6 미만에서는 `system`이 한국어 안내와 함께 실패해야 한다.
6. 녹음 중 마이크를 뽑는다: 로그에 오류가 남고, 앱이 멈추지 않고, 다시 연결을 시도한다. 다시 꽂으면 상태 줄의 소리 입력 오류가 사라진다.
7. macOS 입출력 겸용 장치(AirPods, USB 헤드셋)를 출력·입력으로 연결한다. 음악을 틀고 말한다. `system`에는 음악만, `mic`에는 목소리만 있어야 한다.
8. macOS: `system` 녹음 중 AirPods를 연결한다. 로그에 장치 변경이 남고, 앱에 멈춤 안내 뒤 다시 받기 안내가 보이고, 변경 뒤 음악도 파일에 있어야 한다.
9. Windows: 앱이 소리를 받는 중에 기본 출력을 블루투스 헤드셋으로 바꾼다. 멈춤 안내 뒤 다시 받기 안내가 보이고 새 장치에서 계속 받아야 한다.
10. Windows: 설정 › 개인 정보 › 마이크 접근을 끈다. 시작이 한국어 개인 정보 안내와 함께 실패해야 한다. macOS: 마이크 권한을 거부하면 `mic`에만 「3초 동안 소리가 전혀 들어오지 않습니다」 안내가 한 번 보인다.
11. macOS: AirPods를 출력으로 `system`을 녹음하며 음악을 튼다. 다른 터미널에서 AirPods 마이크로 `mic`를 시작한다. `system` WAV의 음높이와 속도가 바뀌지 않아야 하고, 로그에 멈춤 한 번과 다시 시작 한 번이 남아야 한다.
